# 虛擬試穿功能改進文檔

## 📋 問題分析

### 核心問題
生成的圖片與選取的衣物不符，主要原因：

1. **AI 模型限制**
   - Gemini 2.5 Flash Image 將多張衣物圖片當作「風格參考」而非「精確替換指令」
   - 模型傾向於根據整體風格生成新服裝，而不是精確組合輸入的單品
   - 例如：輸入上衣+裙子，卻生成了連衣裙

2. **Prompt 不夠明確**
   - 原始 prompt 沒有明確指示每件衣物的位置和細節
   - 缺少對「精確還原」的強調

3. **缺少追蹤機制**
   - 無法判斷圖片是用實際衣物圖片生成，還是純文字 fallback 生成
   - 日誌不夠詳細，難以診斷問題

```python
tryon_prompt = """🎯 虛擬試穿任務 - 請精確執行以下指令:

🎨 **生成要求** (必須嚴格遵守):

   - 仔細觀察每張衣物圖片的顏色、圖案、材質、剪裁
   - 在生成的圖片中,模特兒必須穿著與這些圖片**完全相同**的服裝
   - 不要創造新的服裝,不要改變顏色或圖案
   - 不要將多件衣物合併成一件(例如:不要將上衣+裙子變成連衣裙)

2. **正確的穿搭組合**:
   - 如果有上衣(tops),穿在上半身

"""
```

**改進點**：
- ✅ 使用 emoji 和結構化格式，提高可讀性
- ✅ 明確列出每張圖片的衣物名稱和類別
- ✅ 強調「精確還原」而非「風格參考」
- ✅ 明確禁止合併衣物（如上衣+裙子→連衣裙）
- ✅ 按類別組織衣物，指定穿著位置

## 🔍 如何診斷問題

### 1. 檢查後端日誌

啟動後端時查看日誌輸出：

```powershell
# 查看後端日誌
.\watch_backend_output.ps1
```

關鍵日誌標記：
- `🎯 開始虛擬試穿圖片生成` - 開始生成
- `📥 下載: ...` - 衣物圖片下載
- `✅ 成功載入` - 圖片載入成功
- `❌ 下載失敗` - 圖片載入失敗
- `🎉 虛擬試穿圖片生成成功!` - 使用實際衣物圖片生成成功
- `🔄 Fallback: 使用純文字生成模式` - 回退到純文字生成

### 2. 檢查前端提示

生成成功後，前端會顯示：
- `✅ 使用 2 張實際衣物圖片生成` - 表示使用了實際衣物圖片
- `⚠️ 僅使用文字描述生成` - 表示回退到純文字模式

### 3. 常見問題排查

| 問題 | 可能原因 | 解決方案 |
|------|---------|---------|
| 生成的衣物不符 | 使用了 text_only_fallback | 檢查衣物圖片 URL 是否可訪問 |
| 圖片下載失敗 | GCS 權限問題或 URL 過期 | 檢查 CORS 配置和 GCS 權限 |
| 模型未返回圖片 | API 配額或網路問題 | 檢查 GEMINI_API_KEY 和網路連接 |
| 衣物合併錯誤 | 模型理解錯誤 | 這是 AI 模型的限制，需要多次嘗試 |

## ⚠️ 已知限制

### 1. AI 模型的固有限制

即使使用了改進的 prompt，Gemini 2.5 Flash Image 仍然可能：
- 將多件衣物合併成一件（如上衣+裙子→連衣裙）
- 改變衣物的顏色或圖案
- 生成與輸入圖片不完全相同的服裝

**原因**：
- 文生圖模型不是專門的虛擬試穿模型
- 缺少 warping（扭曲）和 inpainting（修補）技術
- 沒有使用模特兒原始照片作為基礎

### 2. 真正的虛擬試穿需要

專業的虛擬試穿系統通常需要：
1. **模特兒原始照片** - 作為基礎圖片
2. **姿態估計** - 檢測身體關鍵點
3. **服裝分割** - 精確分離服裝區域
4. **Warping** - 將衣物扭曲以適應身體
5. **Inpainting** - 修補和融合邊緣

這些技術遠超簡單的文生圖模型能力。

## 📈 未來改進方向

### 短期改進（可實施）

1. **多次生成選擇**
   - 一次生成 2-3 張圖片

2. **負面 Prompt**
